## 1. 三个正交概念

上游把「面板停在哪」「按钮画在哪」「窗口是什么形态」拆成三件事，
复刻时必须保持正交，捏成一个「角落」枚举就是错的。

| 概念 | 字段 | 取值 | 出处 |
|---|---|---|---|
| 停靠边 | `anchor` | TOP / LEFT / BOTTOM / RIGHT | `platform/ide-core/src/com/intellij/openapi/wm/ToolWindowAnchor.java:16-21` |
| 同边内的另一半 | `isSplit` | false / true | `platform/platform-impl/src/com/intellij/openapi/wm/impl/WindowInfoImpl.kt:91-92` |
| 窗口形态 | `type` | DOCKED / FLOATING / SLIDING / WINDOWED | `platform/ide-core/src/com/intellij/openapi/wm/ToolWindowType.java:4` |

`anchor` 只有四个值，是个**不可扩展的常量类**（私有构造，`VALUES` 固定四项，
`ToolWindowAnchor.java:21`）。`isHorizontal()` = TOP 或 BOTTOM（同文件 `:49-51`）。

### 1.1 「位置」的真值是 anchor + isSplit，一共 8 个格子

最直白的证据是位置图标的选取（`ToolWindowManagerImpl.kt:770-786 · getLocationIcon`）：

| anchor | isSplit=false | isSplit=true |
|---|---|---|
| LEFT | MoveToLeftTop | MoveToLeftBottom |
| RIGHT | MoveToRightTop | MoveToRightBottom |
| TOP | MoveToTopLeft | MoveToTopRight |
| BOTTOM | MoveToBottomLeft | MoveToBottomRight |

即：竖边（LEFT/RIGHT）上 `isSplit` 分**上下**，横边（TOP/BOTTOM）上分**左右**。
这是「同一条边被切成两格」，不是第五、第六条边。

### 1.2 anchor 与「按钮画在哪」是两件事

新 UI 只有左右两根竖条带，每根条带内部再分**上下两组**
（`platform/platform-impl/src/com/intellij/toolWindow/ToolWindowToolbar.kt:44-45 · topStripe/bottomStripe`）。
落位规则是死的：

| 条带 | topStripe 的 anchor | bottomStripe 的 anchor | 出处 |
|---|---|---|---|
| 左条带 | LEFT | **BOTTOM**（split=false） | `ToolWindowLeftToolbar.kt:11-12` |
| 右条带 | RIGHT | **BOTTOM**（split=true） | `ToolWindowRightToolbar.kt:11-12` |

选条带的函数把这条规则写成了一行：
`ToolWindowPaneNewButtonManager.kt:228-233 · findToolbar` —
`LEFT -> left；RIGHT -> right；BOTTOM -> if (isSplit) right else left`。
`getStripeFor(anchor, isSplit)`（同文件 `:126-139`）在 anchor=BOTTOM 而 `isSplit` 为 null 时直接抛异常，
说明**BOTTOM 的按钮落位必须知道 isSplit**。

**只有 BOTTOM 的 isSplit 会换条带。** LEFT/RIGHT 的 `isSplit` 不换条带，
它让按钮排到**同一组的后半段**，中间插一个分隔符
（`platform/platform-impl/src/com/intellij/openapi/wm/impl/AbstractDroppableStripe.kt:99-105 · useStripeButtonSeparator`，
条件是「新条带 且 anchor 是 LEFT/RIGHT 且无 ToolWindowExtension」）。
排序规则见 `AbstractDroppableStripe.kt:57-72`：`isSplit=false` 一律在前；
新 UI 的 BOTTOM 竖条带里 order 是**倒序**（`:63-67`）。

所以：一个 anchor=BOTTOM、isSplit=false 的工具窗口，**面板停在下边**，
**按钮画在左条带的下半组**。这两件事在上游从来没有被合并过。

新 UI 没有 TOP 条带，BOTTOM 也不占高度：
`ToolWindowPaneNewButtonManager.kt:160-167 · getStripeHeight` 恒返回 0，注释原话是
BOTTOM 的按钮显示在左边，所以没有高度。宽度只有 LEFT/RIGHT 有（同文件 `:154-158`）。

（`extendedToolWindowsUi` 里的 `ToolWindowExtension` 会另外造出真正的 top/bottom 条带
（`ToolWindowPaneNewButtonManager.kt:39-47`、`:236-245 · getHorizontalToolbar`）。
那是可选扩展，**本项目第一阶段不复刻**，按 `ToolWindowExtension.exists == false` 的分支走。）

要点：

- `DEFAULT_WEIGHT = 0.33f` 是常量，写在 `WindowInfoImpl.kt:35`，被多处引用（见 §4、§6）。
- `weight` 和 `sideWeight` 的 setter 会夹到 `[0,1]`：`max(0f, min(1f, it))`（`:87`、`:89`）。
- `toolWindowPaneId` 默认值 `"root"` 来自
  `platform/platform-api/src/com/intellij/openapi/wm/WindowInfo.kt:7 · WINDOW_INFO_DEFAULT_TOOL_WINDOW_PANE_ID`；
  null 一律当作它看（同文件 `:53-54 · safeToolWindowPaneId`）。
  **多 pane 是分离窗口用的**，单窗口复刻里恒为 `"root"`，但字段要留着，别在模型里省掉。
- `order = -1` 表示「还没定序」，显示时才补：见 §3。
- `anchor` 反序列化失败一律回落 LEFT（`:149-163 · ToolWindowAnchorConverter`）。
- `contentUiType` 未知值回落 TABBED
  （`platform/ide-core/src/com/intellij/openapi/wm/ToolWindowContentUiType.java:26-33`）。
- `type` 有个硬编码修正：`id == "Preview"` 且 type==DOCKED 时强制改成 SLIDING
  （`WindowInfoImpl.kt:131-134 · setTypeAndCheck`）。这是唯一的 id 特判，复刻时照抄或明确不抄。

`ToolWindowType` 的 `isInternal`（`setType` 里用到，`:124-129`）在
`platform/platform-impl/src/com/intellij/openapi/wm/impl/ToolWindowTypeExtensions.kt`，
本轮未审，列入 §9。

## 3. 排序：anchor 权重 + order

出处：`platform/platform-impl/src/com/intellij/openapi/wm/impl/DesktopLayout.kt`。

- 比较器 `windowInfoComparator`（`:190-193`）：先比 anchor 权重，再比 `order`。
- anchor 权重（`:180-188 · getAnchorWeight`）：**TOP=1, LEFT=2, BOTTOM=3, RIGHT=4**。
  注意这套次序只用于排序/序列化，跟视觉位置无关。
- `normalizeOrder`（`:198-214`）：排序后按 anchor 分组，每组 order 从 0 重排；
  `order == -1` 的跳过、保持 -1。读盘后必调（`:127`）。
- `getNextOrder(paneId, anchor)`（`:33-35`）：该 (pane, anchor) 组里最大 order + 1，空组返回 0。
- `setAnchor(info, newPaneId, newAnchor, newOrder)`（`:75-101`）：
  - `newOrder == -1` → 取 `getNextOrder`，即插到该条带末尾；
  - 否则把目标条带里 `order >= newOrder` 的**其他**窗口整体 +1，返回被改动的列表（调用方要同步它们的 UI）。
- 序列化只按 `getSortedList()` 的顺序写（`:147-167 · writeExternal`），`id` 为空的条目读盘时丢弃并告警（`:113-116`）。

## 4. 统一权重（unified weights）

出处：`platform/platform-impl/src/com/intellij/openapi/wm/impl/UnifiedToolWindowWeights.kt`。

- `@Tag("unified_weights")`，四个 Float：`top/left/bottom/right`，
  默认全是 `WindowInfoImpl.DEFAULT_WEIGHT`（`:20-23`）。
- 挂在 `DesktopLayout` 上（`DesktopLayout.kt:22`），随 layout 一起读写（`:122-131`、`:161-164`）。

**什么时候生效**：`ToolWindowManagerImpl.kt:647 · isUnifiedToolWindowSizesEnabled` = `!isIndependentToolWindowResizeEnabled()`，
而后者（`:649-656`）在新 UI 下读 `UISettings.rememberSizeForEachToolWindowNewUI`，
其默认是 **false**（`platform/editor-ui-api/src/com/intellij/ide/ui/UISettingsState.kt:97`）。

所以**新 UI 默认走统一权重**：每次激活工具窗口时，用该 anchor 的统一权重覆盖窗口自己的 `weight`
（`ToolWindowManagerImpl.kt:612-615`）。也就是说同一条边上的所有窗口共享一个宽度。
旧 UI 默认相反（`rememberSizeForEachToolWindowOldUI` 默认 true，`UISettingsState.kt:95`）。

## 5. 默认摆放

出处：`platform/platform-impl/src/com/intellij/toolWindow/defaultToolWindowlayoutProvider.kt`。
默认布局由扩展点 `com.intellij.defaultToolWindowLayout` 拼装（`:26`），
平台自带的那个扩展只是把三根条带的平台默认值加进去（`:173-185`）。
V1 = 旧 UI，V2 = 新 UI，选哪个看 `ExperimentalUI.isNewUI()`
（`ToolWindowDefaultLayoutManager.kt:54`）。**本项目复刻 V2。**

### V2（新 UI，`:254-288 · addPlatformDefaultsV2`）

| anchor | id | weight | isSplit | contentUiType |
|---|---|---|---|---|
| LEFT | `Project` | 0.25 | false | **COMBO** |
| LEFT | `Commit` | 0.25 | false | TABBED |
| LEFT | `Structure` | 0.25 | **true** | TABBED |
| RIGHT | `Notifications` | 0.25 | false | **COMBO** |
| RIGHT | `AIAssistant` | 0.25 | false | TABBED |
| RIGHT | `Database` | 0.25 | false | TABBED |
| RIGHT | `Gradle` | 0.25 | false | TABBED |
| RIGHT | `Maven` | 0.25 | false | TABBED |
| BOTTOM | `Version Control` | 0.33 | false | TABBED |
| BOTTOM | `Problems` | 0.33 | false | TABBED |
| BOTTOM | `Problems View` | 0.33 | false | TABBED |
| BOTTOM | `Terminal` | 0.33 | false | TABBED |
| BOTTOM | `Services` | 0.33 | false | TABBED |

没写 weight 的取 builder 默认 `WindowInfoImpl.DEFAULT_WEIGHT`=0.33（`:308`）；
`isVisible` 一律 false、`sideWeight` 一律 0.5（`:307`、`:311`）。

`order` 不是在这里写的：`build()` 按 left→right→bottom 的顺序遍历，
**每根条带内部**按加入顺序 `withIndex()` 赋 0,1,2…（`:210-218 · add`）。
所以上表的行序就是 order。

BOTTOM 那五个全是 `isSplit=false` → 按 §1.2 全部落在**左条带的下半组**。
默认布局里没有任何窗口落在右条带下半组。

TOP 在这套 API 里是非法的：三处 `addPlatformDefaults*` 遇到 TOP 直接抛
`UnsupportedOperationException("The top stripe is not supported")`（`:234`、`:256`），
`DefaultToolWindowLayoutBuilder` 也只暴露 `left/right/bottom` 三个属性（`:42-44`）。
**anchor=TOP 在模型里合法（枚举有它、排序有它、几何有它），但默认布局构造不出来。**

### V1（旧 UI，`:232-252`）——只作对照，不复刻

LEFT: `Project`(0.25, COMBO)；RIGHT: `Notifications`(0.25)；
BOTTOM: `Version Control`, `Find`, `Run`, `Debug`(0.4), `Inspection`(0.4)。

### 存盘形态

`ToolWindowDefaultLayoutManager`（`platform/platform-impl/src/com/intellij/toolWindow/ToolWindowDefaultLayoutManager.kt`）
是应用级服务，存 `window.layouts.xml`（`:29-32`）。
一份存档里可以有多套具名布局（`layouts: Map<String, ToolWindowLayoutDescriptor>`，`:139`），
每套内部再分 `v1`/`v2` 两份（`:186-190`）。初始布局名 `"Custom"`，
工厂默认布局名是空串（`:38-39`），且空串这套不允许被覆盖保存（`:69-74`）。
`ToolWindowDescriptor` 是序列化用的扁平 DTO（`toolwindow.kt:96-125`），字段与 `WindowInfoImpl` 一一对应，
`floatingBounds` 在这里是 `List<Int>`(x,y,w,h)（`ToolWindowDefaultLayoutManager.kt:242`）。

## 6. 停靠几何

出处：`platform/platform-impl/src/com/intellij/toolWindow/ToolWindowPane.kt`。

### 6.1 两层 ThreeComponentsSplitter

`verticalSplitter`（TOP=first，BOTTOM=last）与 `horizontalSplitter`（LEFT=first，RIGHT=last），
映射见 `:301-310 · setComponent`。两者互相嵌套，谁在外看 `UISettings.wideScreenSupport`（`:176-186`）：

- `wideScreenSupport = false`（**默认**，`UISettingsState.kt:93`）→ 外层是 `verticalSplitter`，
  内层是 `horizontalSplitter`。即 **TOP/BOTTOM 通栏，LEFT/RIGHT 夹在中间**。
- `= true` → 反过来，LEFT/RIGHT 通栏。

分隔条 `dividerWidth = 0`，鼠标热区另给（`:196-201 · setUpSplitter`）。

### 6.2 weight → 像素

`:315-355 · setWeight`：`anchorSize = rootPane.size 的宽或高 × weight`，
横边（TOP/BOTTOM）乘高，竖边（LEFT/RIGHT）乘宽；然后写进对应 splitter 的 `firstSize`/`lastSize`。
rootPane 尺寸还是 0 时会挂个 resize 回调重试（`:322-332`）。

`normalizeWeight`（`:85-90`）：`<= 0` → 0.33；`>= 1` → `1 - 0.33 = 0.67`；否则原值。
所有下发到 splitter 的 weight 都过这一道。

反向（拖动后回算 weight）用 `ToolWindowManagerImpl.kt:228-232 · getAdjustedRatio`：
`ratio = part/total`，再 `ratio += ((part+direction)/total - ratio) / 2`，direction 取 ±1。
调用点 `ToolWindowPane.kt:920-924`。

### 6.3 同一格里的两个窗口（split）

`:230-252 · addDecorator`：先用 `manager.getDockedInfoAt(paneId, anchor, !info.isSplit)`
（`ToolWindowManagerImpl.kt:760-764`）问「对面那半格有没有可见的停靠窗口」。
没有 → 独占整格；有 → 走 `addAndSplitDockedComponentCmd`（`:611-741`）造一个 `OnePixelSplitter`。

- splitter 方向 = `anchor.isSplitVertically`（`:655`），
  该属性定义在 `ToolWindowAnchor.java:63-66`：
  `LEFT && !UISettings.leftHorizontalSplit || RIGHT && !UISettings.rightHorizontalSplit`。
  两个 UISettings 默认都是 false（`UISettingsState.kt:99`、`:101`），
  **所以左右边默认是竖着切（上下两块）**，与 §1.1 的图标命名一致。
- 摆放：`isSplit=true` 的窗口是 **second**，`isSplit=false` 的是 **first**（`:703-706`、`:721-722`）。
- 比例：`isSplit=false` 进来时 `proportion = normalizeWeight(info.sideWeight)`（`:722`）；
  `isSplit=true` 进来时 `proportion = normalizeWeight(old.sideWeight / (old.sideWeight + new.sideWeight))`（`:707-711`）。
- 整格的 weight：竖边且竖切时取 `normalizeWeight(单个 weight)`；
  竖边且横切（并排）时取 `normalizeWeight(old.weight + new.weight)`（`:712-717`、`:723-728`）。
- 撤走其中一个时，剩下那个从 splitter 里取出来直接占整格，
  weight 用它自己的（`:264-283 · removeDecorator`）。

### 6.4 SLIDING / FLOATING / WINDOWED

- DOCKED 走上面的 splitter；SLIDING 走 `addSlidingComponent`（`:245-247`、`:743` 起），
  贴在 layeredPane 的 palette 层上，按 `info.weight` 定尺寸（`:929-955 · setBoundsInPaletteLayer`）。
- FLOATING / WINDOWED 不进 pane，由 `decorators.addFloatingDecorator` / `addWindowedDecorator` 处理
  （`ToolWindowManagerImpl.kt:942-947`）。

## 7. 行为规则

出处：`platform/platform-impl/src/com/intellij/openapi/wm/impl/ToolWindowManagerImpl.kt`。

### 7.1 同一格里只能有一个可见（这是最核心的一条）

`:940-1006 · doShowWindow`：要显示 X 时，遍历所有别的窗口，凡是满足
**`isVisible` 且 `type` 相同 且 `isSplit` 相同 且 `paneId` 相同 且 `anchor` 相同**
的，一律隐藏（`:962-966`）。被挤掉的那个，如果是 DOCKED 且非 autoHide，就压进 `sideStack`（`:976-977`）。

所以「格子」的完整键是 **(paneId, anchor, isSplit, type)**，一格一个可见窗口。
不是每边一个 —— LEFT 的上下两半可以同时可见。

### 7.2 隐藏时自动恢复

`:856-909 · executeHide`：
- `hideSide = true`：把同一 (pane, anchor) 上所有可见窗口全隐掉，并清空该 anchor 的 sideStack（`:867-880`）。
- 否则：从该 anchor 的 sideStack 往外弹，**跳过 isSplit 不一致的**（`:889-891`），
  再校验 pane/anchor/type/autoHide 四项都没变过（`:896-899`），
  找到就把它重新显示出来（`:903-906`）。

### 7.3 显示

`:916-938 · showToolWindowImpl`：置 `isVisible = true`、**强制 `isShowStripeButton = true`**、
`order == -1` 时补 `getNextOrder`（`:927-931`）。然后拿一份 `copy()` 作为只读快照下发给 UI
（`:933-935`）——上游严格区分「可变的 layout info」和「entry 持有的只读快照」，复刻要保留这个分工。

### 7.4 激活

`:598-645 · activateToolWindow`：
1. 若统一权重启用（§4），先用 anchor 的统一权重覆盖 `info.weight`（`:606-609`）；
2. 把 id 挪到 `recentToolWindowsState` 首位（`:615-616`）；
3. 不可见 → 置 `isActiveOnStart = autoFocusContents` 并 show（`:630-633`）；
4. 焦点给不出去时压 `activeStack`（`:641`）。

隐藏的对称操作 `:698-704 · setHiddenState`：`isActiveOnStart = false`、`isVisible = false`、
从 `activeStack` 移除。

### 7.5 改 anchor / 改 isSplit

- `setToolWindowAnchor(id, anchor, order = -1)`（`:1508-1528`）：anchor 与 order 都没变就直接返回。
- `:1538-1584 · setToolWindowAnchorImpl`：窗口不可见、或只改了 order、或是 FLOATING/WINDOWED
  → 只挪按钮；否则先 `isVisible = false` + 摘掉 decorator，改完再 `showToolWindowImpl` 重放（连焦点一起还原）。
- `:1586-1620 · doSetAnchor`：**新 UI 下必须按「旧的 anchor + 旧的 isSplit」去删旧按钮**（`:1595-1596`），
  否则会去错条带。然后 `layoutState.setAnchor(...)` 连带修正别人的 order（§3），
  最后按 `isShowStripeButton || isVisible` 决定要不要建新按钮（`:1612-1618`）。
- `:1635-1652 · setSideTool`：改 `isSplit` 的做法是「先隐藏，改，再显示」
  （`hideIfNeededAndShowAfterTask`，`:1686` 起），借 §7.1 的互斥逻辑自动把新格子里的旧住户挤走。

### 7.6 按钮的存在性

- `isShowStripeButton` 只是「用户想不想要这个按钮」，**可见时无条件忽略它**
  （`doSetAnchor` 的注释与条件，`:1612-1613`；`showToolWindowImpl` 里强制置 true，`:928`）。
- 条带整体的可见性：`updateToolStripesVisibility`（`ToolWindowPaneNewButtonManager.kt:76-99`）——
  一根条带没有任何可见按钮就整根隐藏。

## 8. 复刻到 C# 时的直接结论

1. `WindowInfo` 建成不可变 record + 可变 builder 两份，对应上游
   「layout 里的可变 `WindowInfoImpl`」与「entry 上的只读快照」（§7.3）。
2. 格子的键用 `(PaneId, Anchor, IsSplit, Type)` 四元组，别用「角落」枚举（§7.1）。
3. 按钮落位是**派生量**，由 `(Anchor, IsSplit)` 算出 `(条带, 上/下组)`，不进持久化（§1.2）。
4. 默认布局按 §5 的 V2 表硬编码，order 由「加入顺序」生成，不写死数字。
5. weight 的所有出入口都过 `NormalizeWeight`（§6.2），夹取在 setter 里做（§2）。
