# 上游审读：编辑区（标签页与分屏）

审读对象：`third_party/intellij-community/`，路径与标注约定同前两份。

**为什么 Forge 要做这块**：Forge 与 Bench 是两个独立的库，各自要为自己那个形态**完整**。
上游把编辑区放在 `fileEditor` 包、工具窗口放在 `wm` 包，那是 IntelliJ 的分包方式，
不是 Forge 的边界 —— 一个"Rider 形态"的库不带编辑区没法用。
行为与数字仍然照上游审，这条不变。

主要读的是：

| 文件 | 里面是什么 |
|---|---|
| `platform/platform-impl/src/com/intellij/openapi/fileEditor/impl/EditorsSplitters.kt` | 分屏树、存档 |
| 同目录 `EditorWindow.kt` | 一组标签页：开合、选中、分屏、上限 |
| 同目录 `EditorTabbedContainer.kt` | 标签页容器 |
| `platform/platform-impl/src/com/intellij/platform/fileEditor/FileEntry.kt` | 单个标签页的存档字段 |
| `platform/platform-api/src/com/intellij/ui/tabs/impl/` | `JBTabs` 的度量与画法 |

---

## 1. 三层结构

```
EditorsSplitters          整个编辑区（一棵二叉分屏树的根）
  └ Splitter              一次分屏：first / second + 方向 + 比例
      └ EditorWindow      一组标签页（叶子）
          └ 标签页 × N     一个文件一个
```

- **分屏树是二叉的**：每个 `Splitter` 只有 `firstComponent` / `secondComponent`
  （`EditorsSplitters.kt:1270-1279`）。三栏是"分屏里再分屏"，不是一个三元节点。
- **叶子才有标签页**：`EditorWindow` 是唯一持有标签页的东西。
- `EditorsSplitters` 记着「当前是哪个 window」（`currentWindow`），
  拖拽、新开文件都落在它身上。

## 2. 标签页

### 2.1 关掉一个之后选中谁

这是最容易做错、也最影响手感的一条。出处
`EditorWindow.kt:766-782 · getTabToSelect` → `:825-855 · computeIndexToSelect`：

1. **被关的那个记得"上一次选中的是谁"**（`tabBeingClosed.previousSelection`），
   只要那个还在，就选它（`:771-777`）。
2. 否则算下标：
   1. **被关的不是当前选中的** → 选中不动（`:826-830`）；
   2. `activeMruEditorOnClose` → 沿历史往回找第一个还开着的（`:833-848`）；
   3. `activeRightEditorOnClose` 且右边还有 → **右邻居**（`:849-851`）；
   4. 都不是 → **左邻居**；它已经是第一个就返回 -1（`:853-854`）。

两个开关的默认值（`platform/editor-ui-api/src/com/intellij/ide/ui/UISettingsState.kt`）：

| 设置 | 默认 | 行 |
|---|---|---|
| `activeMruEditorOnClose` | false | 159 |
| `activeRightEditorOnClose` | `PlatformUtils.isAppCode()` —— 非 AppCode 即 **false** | 162 |

**所以默认行为是：先按"上一次选中"，否则选左邻居。**

### 2.2 标签页上限

`EditorWindow.kt:1049-1092 · trimToSize / doTrimSize`：

- 上限 `editorTabLimit` 默认 **30**（`UISettingsState.kt:68`）；
  专注模式且标签页设为"不显示"时强制为 1（`EditorWindow.kt:122-130`）。
- 超限之前先做两件事：
  1. 选中的那个若"该被关"就先关（`:1062-1068`）；
  2. **所有预览标签页一律关掉**（`:1071-1073`）。
- 判定是否超限时，**不算那些不允许关闭的标签页**
  （`:1076` 减去 `tabsExcludedFromLimitCount()`，`:1180-1182`）。
- 关闭顺序 `getTabClosingOrder`（`:1094` 起）：
  1. **先关不在历史里的**（`:1099-1104`）；
  2. `closeNonModifiedFilesFirst`（默认 false，`UISettingsState.kt:157`）时，
     再按历史顺序关未修改的。
- **固定住的永远不被挤掉**：`fileCanBeClosed` 要求 `!isFilePinned(file)`（`:1173-1178`）。

### 2.3 固定（pin）

`isPinned` 在标签页自己身上（`EditorWindow.kt:1028`、`:1036-1037`），
分屏时新窗口会继承被分出去那个文件的 pin 状态（`:580`）。

## 3. 分屏

### 3.1 分出去

`EditorWindow.kt:518-585 · split`：

- **`tabCount < 1` 直接返回 null**（`:528-530`）—— 空组分不了屏。
- 不强制分屏且**已经在分屏里** → 不再分，直接在**第一个兄弟**里打开（`:533-544`）。
- 真分屏时：造一个 `Splitter`，**比例固定 0.5，可拖范围 [0.1, 0.9]**（`:549`）。
- `fileIsSecondaryComponent`（默认 true）决定新组放在 first 还是 second（`:559-566`）。
- **只把选中的那个文件带过去**，不是把整组标签页复制过去
  （`:570-571` 的注释原话："open only selected file in the new splitter instead of opening all tabs"）。

### 3.2 合回来

`EditorWindow.kt:939-980 · unsplit`：

- 把所有兄弟组的标签页搬进本组，**搬的时候仍然守 `editorTabLimit`**：
  超了就直接 dispose 掉那个 composite，不搬（`:955-967`）。
- 搬完选中谁：优先本组原来选中的，否则第一个兄弟组选中的（`:944`）。
- `unsplitAll`（`:983-988`）就是循环 unsplit 到不在分屏里为止。

### 3.3 关掉一个组

`EditorWindow.kt:791-820 · removeFromSplitter`：
父节点是 `Splitter` 就把**另一半提升上去**顶替整个 splitter；
父节点已经是根（`EditorsSplitters`）就直接换根的内容。
这就是"二叉树删除一个叶子"的标准做法。

## 4. 存档

分屏树递归写（`EditorsSplitters.kt:1267-1294 · writePanel`）：

```xml
<splitter split-orientation="vertical|horizontal" split-proportion="0.5">
  <split-first>  …再一层 splitter 或 leaf… </split-first>
  <split-second> … </split-second>
</splitter>
```

- `split-orientation`：`component.orientation` 为真写 `vertical`（`:1271`）；
  读回来 `isVertical = 值 == "vertical"`（`:1326`）。
- `split-proportion`：读不到时**兜底 0.5**（`:1329`）。
- 叶子写成 `<leaf>`，里面每个标签页一个 `<file>`（`FileEntry.kt:102`）。

单个标签页的属性（`FileEntry.kt:32-33`、`:115-122`）：

| 属性 | 含义 |
|---|---|
| `pinned` | 固定住了 |
| `current-in-tab` | 这组里当前选中的是它 |
| （还有 `EXCLUDED_FROM_TAB_LIMIT`） | 不计入标签页上限 |

同样是**只写与默认不同的**：`pinned` / `current-in-tab` 只在为真时写出来。

## 6. 复刻到 C# 的直接结论

1. 分屏树建成**二叉树**：节点要么是 `Split(方向, 比例, 左, 右)`，要么是 `Group(标签页…)`。
2. "关掉之后选谁"单独做成一个纯函数，把 §2.1 那四条按顺序实现，用例逐条钉。
   **默认路径是「上次选中 → 左邻居」**，不是"右邻居"。
3. 标签页上限、pin、预览的相互作用（§2.2）也做成纯函数：
   固定住的永远不参与淘汰，不可关闭的不计入分母。
4. `split` 只把**选中那一个**带过去；`tabCount == 0` 时不允许分屏。
5. 存档用 §4 的形状，属性名照抄。

## 7. 本轮没审的

- `EditorComposite`：一个文件可以有多个编辑器（文本 / 设计视图）并排切换。
  Forge 的"一个标签页 = 一块内容"是更简单的模型，暂不做这一层。
- 标签页拖拽产生分屏的落点判定（`showSplitChooser` / `MySplitPainter`，`EditorWindow.kt:865` 起）。
- 预览标签页（`isPreview`）的完整语义，只确认了"超限时先关它们"。
