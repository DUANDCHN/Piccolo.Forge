# 宿主接入指南

这份文档只回答一个问题：**哪些事归库，哪些事归你**。

代码示例全部取自 `samples/Piccolo.Forge.Sample`，那是能编译能跑的；
真要照抄就抄那个文件，别抄这里（这里为了讲清楚做了删减）。

---

## 0. 三分钟版本

```csharp
// ① 你的面板：继承 ToolWindowPanel，它就是一块停在边上的工具窗口
internal sealed class ProjectTool : ToolWindowPanel
{
    public ProjectTool() : base("Project") { Title = "项目"; Icon = myIcon; }
}

// ② 外壳 VM：宿主的接入点
var shell = new ToolWindowShellViewModel();

// ③ 登记：把面板交出去，只说「停哪条边、哪一半」
shell.Add(new ProjectTool(), ToolWindowAnchor.Left);
shell.Add(new StructureTool(), ToolWindowAnchor.Left, isSplit: true);

// ④ 控件接上就完事
var frame = new ForgeControl();
frame.Attach(shell);          // 等价于 frame.Shell = shell
```

⚠ **还有一句不能忘 —— 装主题**（在 `Application` 起来时、外壳控件挂树之前）：

```csharp
ForgeThemeManager.Apply(app, ForgeThemeFamily.ExpUi);   // 或 Islands
```

不装就没有 `ControlTheme`，控件**什么都不画且不报错**。详见 §5.0a。

**或者整块写在 XAML 里** —— `Shell` / `Area` 都是可绑定属性（对位 Dock 的
`<DockControl Layout="{Binding Layout}"/>`）：

```xml
<forge:ForgeControl Shell="{Binding Shell}">
  <forge:ForgeControl.EditorContent>
    <forge:ForgeEditorControl Area="{Binding Editor}"/>
  </forge:ForgeControl.EditorContent>
</forge:ForgeControl>
```

⚠ **只有"接哪个 VM"能写进 XAML。** 外观里的取色回调、外部窗体工厂是委托，仍得在 C# 里给
（Dock 那边同样如此——它的 `HostWindowLocator` 是个 `Func` 字典）。

配色、条带按钮落位、开合互斥、拖拽、存档格式——都不用你写。

## 1. 边界

| 归库 | 归你 |
|---|---|
| 面板的**身份**（id / 标题 / 图标字段） | 图标画什么 |
| 面板**停在哪**（anchor + isSplit）与按钮落位 | 一开始摆哪 |
| 「一格一个可见窗口」的互斥（§7.1） | 被挤掉之后做什么（暂停采集之类） |
| 开合、激活、拖拽换位、拖分隔条改大小 | — |
| 条带 / 标题条 / tab 的全部度量与配色 | — |
| 明暗跟随宿主的变体自动切 | 宿主自己的明暗设置 |
| 存档的**格式**（`ToolWindowLayoutSerializer`） | 存到哪、什么时候存 |
| 面板内容的**槽**（`Content` 是 `object`） | 内容 VM、视图怎么解析 |

一句话：**库管"工具窗口这套机制"，你管"里面装什么、什么时候动"。**

### 为什么内容是 `object`

`ToolWindowViewModel.Content` 和 `IForgePanel.Icon` 都是 `object`。
控件库不认识你的视图，也不该替你选图标库。你塞 VM 进去，
视图由**你自己的** ViewLocator / DataTemplate 解析——库这边就是个 `ContentControl`。

## 2. 选哪个包

面板基类有**两种绑定**，二选一：

| 包 | 依赖 | 什么时候选 |
|---|---|---|
| `Piccolo.Forge.Mvvm` | 无 MVVM 框架 | 默认选这个 |
| `Piccolo.Forge.Mvvm.CommunityToolkit` | CommunityToolkit.Mvvm | 你的派生面板要用 `[ObservableProperty]` / `[RelayCommand]` |

两个包里的类**同名同形**（`ForgePanelBase` / `ToolWindowPanel` / `EditorPanel`），
换绑定只用改 `using`。

这个分法抄的是 Dock.Avalonia：`Dock.Model` 不引框架只出接口，
`Dock.Model.Mvvm` 才依赖 CommunityToolkit 出基类，另有 `Dock.Model.Avalonia`
是同一套模型的另一种绑定。**接口在中立包、基类按框架分包**——
不这么分，库一旦自带一个 `ObservableObject`，宿主的源生成器就会失灵
（LDVision 接入时当场撞过 CS0104）。

`Piccolo.Forge.Model` 和 `Piccolo.Forge.Mvvm` 都**不引 Avalonia、不引任何 MVVM 框架**，
有用例检查程序集引用钉住这条。

## 3. 面板的两种类型

```csharp
public interface IToolWindowPanel : IForgePanel;   // 停在四条边上
public interface IEditorPanel     : IForgePanel;   // 活在中间那块
```

两个都是**空标记接口**——照 Dock 的 `ITool`（那个接口也是 0 个成员）。

**继承哪个类就决定了停靠方式**，你不用在每处再说一遍；
而且「把编辑区面板停到侧边」**编译期就不成立**。

上游把两者放在不同的包（`wm` vs `fileEditor`），那是 IntelliJ 的分包方式；
**Forge 两块都做** —— 一个「Rider 形态」的库不带编辑区没法用。
编辑区的行为与数字同样照上游审，见 [编辑区](../upstream/编辑区.md)。

## 4. 位置怎么说

```csharp
shell.Add(panel, ToolWindowAnchor.Bottom, isSplit: true);
```

只有两个自由度：

- `anchor` —— 停哪条边（`Top` / `Left` / `Bottom` / `Right`）
- `isSplit` —— 同一条边被切成两半，占哪一半

**没有「四个角」这种东西。** 按钮画在哪根条带是**算出来的**
（`StripePlacementResolver.Resolve`）：

| anchor | isSplit | 面板停在 | 按钮画在 |
|---|---|---|---|
| Left | false | 左边上半 | 左条带上组 |
| Left | true | 左边下半 | 左条带上组（分隔符之后） |
| Right | false / true | 右边上 / 下半 | 右条带上组 |
| Bottom | **false** | 下边左半 | **左**条带下组 |
| Bottom | **true** | 下边右半 | **右**条带下组 |

最后两行是最容易搞错的地方：**anchor=Bottom 的面板停在下边，按钮却在左/右条带上**。
上游把「面板停在哪」和「按钮画在哪」分开，Forge 照做。详见
[工具窗口模型](../upstream/工具窗口模型.md) §1。

新 UI 没有 `Top` 条带，登记到 `Top` 会抛异常（上游的默认布局也构造不出 TOP）。

## 5. 你多半需要接的几件事

### 5.0a 装主题：一句话，且**换主题要重启**

Forge 自带两套**各自完整**的主题（经典 expUI / Islands），它们不共用任何文件。
装哪一套只经一个入口：

```csharp
ForgeThemeManager.Apply(app, family);   // 全仓唯一装 Forge 主题的地方
```

时机是死的：**读完你自己的配置之后、外壳控件挂树之前**。装晚了首帧没有模板（什么都不画、
不报错）；装早了还不知道用户选的是哪一档。

⚠ **换主题要重启，这不是偷懒。** 实测（`ThemeSwapSpikeTests`）：运行时换掉
`Application.Styles` 里的单元，**已经挂在树上的控件不会重新解析 `ControlTheme`**，
翻明暗变体也不会。硬切的结果是最坏的一种：C# 侧按新族算几何取色、模板还是旧族画的。
所以设置页只写配置 + 提示重启（LDVision 就是这么做的）。

⚠ **两个开关必须同族**：装了哪套主题、`Appearance.Family` 是哪族。
不一致时 Debug 下会当场抛（`ForgeThemeManager.AssertConsistent`）——
它拦的正是"引的是 expUI、Family 却是 Islands"这种只在局部露馅、肉眼极难归因的状态。

#### 添加第三个主题的步骤清单

这份清单能不能写短，本身就是 REQ-068 的架构验收。它是三步：

1. `ForgeThemeFamily` 加一个枚举值（名字就是目录名）；
2. `Piccolo.Forge.Avalonia/Themes/<新名字>/` 放一份 `Theme.axaml` + 全部控件主题，
   `Piccolo.Forge.Themes/Themes/<新名字>/Colors.axaml` 放本族颜色；
   照着 `ExpUi/` 复制改是正路 —— **缺哪个控件、缺哪个键，`ForgeThemeCompletenessTests` 当场报红并点名**；
3. `ForgePalette.ForTheme` 给新族返回一份配色。

**既有单元一行都不用动**，宿主也只是多一个可选项。

### 5.0 外观：一个对象，别设两遍

外框与编辑区是两个控件，但外观是**一份**。给外框设上，编辑区自动跟着：

```csharp
frame.Appearance = ForgeAppearance.Default with
{
    Family            = ForgeThemeFamily.Islands,   // 族（与明暗正交）
    PaletteResolver   = (family, variant) =>        // 想微调配色时才给
        ForgePalette.ForTheme(family, variant) with { IslandBorder = ... },
    IslandMetrics     = ForgeIslandMetrics.Default with { BorderWidth = 3 },
    HeaderTitleFontWeight = FontWeight.Black,       // 面板标题条 ┐ 同一件事
    TabTitleFontWeight    = FontWeight.Bold,        // 文档标签   ┘ 的两半
    HeaderHeight = 31,                              // 面板标题条 ┐ 同上
    TabRowHeight = 31,                              // 文档标签行 ┘
};
```

它是 record，改一处用 `with`：`frame.Appearance = frame.Appearance with { Family = … };`
——**整个对象换掉才有变更通知**，所以别指望改字段（也改不了，是 `init`）。

传播规则只有两条：

| 情况 | 怎么到手 |
|---|---|
| 编辑区摆在 `frame.EditorContent` 里 | **自动**（继承式附加属性 `ForgeChrome.Appearance`），你不用管 |
| 编辑区独立使用；文档浮出去的那些窗口 | 库显式传**整份**过去；你自己 new 的那个自己给一份 |

想让某块跟别处不一样，就在那个控件上单设一份——继承的常规规矩，不必再找开关。

> 早先这些是两个控件各一套的散装属性。代价是每样都要设两遍（漏一边 = 四边是岛、中间还是方角），
> 而库内部每个传播点还得手抄一遍——`FloatOut` 就抄漏过取色回调 / 字重 / 行高，
> 表现是文档浮出去之后描边没了、字重和行高变回默认。打成一个对象之后，漏抄在语法上不可能。

### 5.0a 窗口变大时，面板跟着长还是图像区跟着长

默认跟着长——`weight` 是**占这条边的比例**（上游 `ToolWindowPane.kt:315-355`），
窗口一变宽两侧面板一起变宽，中间那块的占比原地不动。IDE 里合理：两边装的是同样要长的树和列表。

内容是一幅要尽量大的画面（相机、地图、画布）时，这就是在浪费屏幕。打开这个开关：

```csharp
frame.KeepAnchorSizeOnResize = true;   // 面板拉多宽就一直多宽，多出来的地方全给中间
```

- 真值变成**像素**：停靠与取消停靠（覆盖层）共用同一把锁，两种形态之间来回切宽度不会自己变。
- 锁只在 `weight` 被外面改了（拖拽 / 读档 / 恢复默认布局）时作废，然后按新 `weight` 重锁一次。
- 窗口缩得比面板还窄时面板跟着缩，不会把编辑区挤成负数。
- **存档格式不变**：库按当前 pane 反算出等价 `weight` 回抛（`ForgeDockPane.AnchorWeightRebased`，
  `ForgeControl` 已经接好写回台账），所以"关窗时多宽、下次开起来还是多宽"。

### 5.0b 按需面板：给工厂，别给实例

```csharp
shell.Add("Histogram", "直方图", ToolWindowAnchor.Bottom,
          () => new HistogramViewModel(),      // ← 第一次真被打开时才跑
          isSplit: true, icon: myIcon);
```

按钮从启动就全都在，实例等到面板真被打开才造。

⚠ **别自己去找「该造了」的时机**：用户点条带按钮走的是**库内部**的开合，
宿主插不上手。漏掉那条路的结果是「按钮点了、面板开了、里面是空的」——
不报错，只是空白，很难往「没人创建内容」上想。

### 5.1 面板不可见就别再干活

库给的是**信号**，策略你定：

```csharp
shell.StateChanged += (_, _) =>
{
    foreach (var vm in shell.ToolWindows)
        if (vm.Content is IPausable p) { if (vm.IsOpen) p.Start(); else p.Stop(); }
};
```

`IsOpen` / `IsActive` 都带属性变更通知，绑到 UI 上也行。

### 5.2 切语言

改面板自己的 `Title` 就够了，会自动跟到条带提示与标题条。
**别在别处再存一份标题**——两份就会分叉。

### 5.3 图标

面板的 `Icon` 是 `object`，三种东西都收：

| 你给的 | 库怎么办 |
|---|---|
| `Geometry` | 直接画（等比缩放居中），颜色跟着状态走 |
| `Control`（`MaterialIcon`、`Image`、任何控件） | 挂成子元素，摆到图标位上由它自己画；库把当前前景色写在 `Foreground` 上，**继承 Foreground 的图标控件会跟着主题明暗与激活态变色** |
| `null` | 条带按钮画 `ForgeIcons.DefaultToolWindow` 那个空框；编辑区标签页**不画**（文件是什么类型只有你知道） |

库自带的 `ForgeIcons` 只有它自己要用的那几个（关闭、图钉、更多、分屏、默认图形），
按 16×16 画、显示时缩放到审出来的图标区（条带 20 / 紧凑 16，编辑区标签页 16）。
**领域图标你自己给** —— 比如 LDVision 用的是它既有的 Material.Icons。

编辑区标签页的图标从 `EditorTabViewModel.Icon` 来，`Open(panel)` 会自动从面板上取。

⚠ **图标控件不能共享**：一个 Avalonia 控件只能有一个父，两个面板拿同一个实例，
第二个挂不上去。每个面板 `new` 一份 —— 图标控件是轻量对象，别为它做缓存。
（放 `Geometry` 没有这个限制，它是不可变的绘图数据，随便共享。）

### 5.4 编辑区

```csharp
var editor = new EditorAreaViewModel();
editor.Open(new ImageDocument("cam-1"));              // 继承 EditorPanel 的面板
editor.Area.Split(editor.Area.CurrentGroup, isVertical: true);

var control = new ForgeEditorControl();
control.Attach(editor);                               // 等价于 control.Area = editor
frame.EditorContent = control;                        // 挂进中间那块
```

规则（都照上游，见 [编辑区](../upstream/编辑区.md)）：
关掉一页之后**默认回到左邻居**（不是右邻居）；标签页上限 30，
超限先关预览页，**固定住的永远不被挤掉**；分屏只把**选中那一页**带过去。

⚠ `EditorTabViewModel.Content` **放数据不要放控件**：分屏之后同一页会同时开在两个组里，
一个 Avalonia 控件不能挂在两个父容器下。放数据由你的 DataTemplate 各渲染一份。

**编辑区的底色**由 `Forge.ExpUi.EditorBackground` / `Forge.Islands.EditorBackground` 两个键给
（同其余颜色，重定义即覆盖、明暗各盖各的）。上游让编辑区比工具窗口深/浅一档，那是给
**满屏文字**的 IDE 定的；宿主的编辑区若常是一整块空画布（图像视口这类），那一档差在暗色下
会读成一个黑洞 —— 想让它与面板同色，覆盖这个键即可，不必去改库里的配色。
分屏叶子跟着同一个键走，不会出现"分屏之后半边亮半边暗"。

### 5.4b 编辑区的两个回调

文档是有资源的（相机会话、图像帧、订阅），所以这两个必须接：

```csharp
editorVm.TabClosed      += (_, tab) => (tab.Content as IDisposable)?.Dispose();
editorVm.ActiveTabChanged += (_, tab) => _activeDocument = tab?.Content;
```

`TabClosed` 对应上游 `EditorWindow.kt:759` 的 `fileClosed` 广播，
`ActiveTabChanged` 对应 `EditorWindow.kt:232-241` 的 `TabsListener.selectionChanged`。
**库不替你 Dispose** —— 内容是你的对象，同一个会话可能还被别处引用着。

### 5.4c 编辑区背板：一张文档都没开时露出来的那一层（可选）

```csharp
control.BackplateFactory = () => new Border
{
    Width = 260, Height = 110,                                  // 与掩码同比例
    Background = watermarkBrush,                                // 颜色跟主题走
    OpacityMask = new ImageBrush(mask) { Stretch = Stretch.Fill },
};
```

**别把彩色 logo 直接摆上去**（第一版就是，一眼就丑）：它带着卡片底、渐变和品牌色，
摆在一片空地上比周围任何东西都重。VS Code / Rider 那种是**单色轮廓** ——
存一张只有 alpha 的掩码图，拿它当 `OpacityMask`，颜色交给主题的一把刷子，
明暗两档各是各的灰而图只存一张。弱化也归颜色管，别叠 `Opacity`。

是个**工厂**而不是一个控件：分屏之后每个叶子都要一份，而一个 Avalonia 控件只能有一个父。
可以在 `Attach` **之后**再配（宿主的外观本来就是建好控件才补的），已经建出来的组会当场跟上。

⚠ **它只在这一组一张文档都没开时才画。**直觉上背板该一直铺着、开了文档自然被盖住 ——
但**文档内容允许透明底**（编辑区底色本来就是给它们当底用的，见 5.4），
一直画的话它会从正文底下透出来，表现为"图像四周一圈水印"。

背板不接鼠标（库替你设了 `IsHitTestVisible = false`），点在空白处仍然只是"点进编辑区"。

### 5.5 存档

两块分开存：工具窗口的摆放，编辑区的标签页 / 分屏树。

```csharp
// 存 —— 在退出、或用户点「保存布局」的时候
var tools  = shell.SaveLayout();                       // <layout>…</layout>
var editor = EditorLayoutSerializer.Write(editorVm.Area);

// 读 —— 一定要在**所有面板都 Add 完之后**
shell.RestoreLayout(tools);
editorVm.Restore(editor, id => ReopenDocument(id));
```

XML 的标签与属性名照抄上游（`window_info` / `anchor` / `side_tool` / `weight`…、
`splitter` / `split-proportion` / `leaf` / `file`），**只写与默认值不同的属性**。
存到哪、什么时候存是你的事。

**两条与版本升级有关的规矩，库替你兜住了：**

| 情况 | 行为 |
|---|---|
| 存档里有这一版**已经删掉**的面板 | 忽略（`RestoreLayout` 只认已登记的 id，返回真正套上去的那批） |
| 存档里**没有**这一版新加的面板 | 保持它的默认摆放 |
| 编辑区某一页宿主认不出来了 | `contentFactory` 返回 `null` 即可，那一页被丢掉并报回给你（与上游解析不到文件时 warn + 跳过一致） |

所以「升级后布局全乱」和「升级后起不来」这两种事不会发生——但**存档坏掉（XML 解析不了）会抛**，
那是宿主该 catch 的：合理的处理是记一条日志 + 退回默认布局，不要让它挡住启动。

## 6. 库故意不做的事

| 不做 | 为什么 |
|---|---|
| **业务图标** | 上游那套是 JetBrains 的美术资产，不描。库自带 `ForgeIcons`（关闭 / 图钉 / 更多 / 分屏 / 默认图形，自己画的），你的领域图标自己给 |
| Alt 双击窥视条带的**键盘钩子** | 状态机 `StripeOverlayState` 已就位，钩子要全局键盘事件，那是宿主的 |
| 内容再嵌套分栏 | 需要「工具窗口内部再嵌 decorator」的模型，比现在深一层 |

## 7. 两个容易踩的坑

**别自己缓存面板控件再手工塞进去。** 控件的复用由 `frame.Sync()` 负责：
状态一变它只改属性、只增删父子关系，**不重建任何已有控件**。
这正是内容能安全地放实时画面 / 图表 / 日志的原因——
有用例数着「内容控件被构造了几次」钉住这条。

**别把明暗钉死。** `Appearance.FollowThemeVariant` 默认开着，跟着宿主走。
钉死一套的结果是系统切浅色时「软件其余部分变白、外壳还是黑的」，中间一道硬边。
真要自己控制，把开关关掉再赋控件的 `Palette`。
