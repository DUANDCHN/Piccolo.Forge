# 发布到 NuGet

发布 = 改版本号 → 提交 → 打 `v*` 标签 → push 标签。其余全由 CI 做，本机不需要任何密钥。

CI **只在打标签时运行**，日常提交不触发；因此推标签前必须在本机跑过测试。

## 步骤

1. **定版本**：改 `Directory.Build.props` 里的 `VersionPrefix` / `VersionSuffix`。
   预览版 `VersionSuffix` 填 `preview.N`，正式版把 `VersionSuffix` 整行删掉。
2. **公开 API 记账**：
   - 预览版之间：新增的公开面留在各库的 `PublicAPI.Unshipped.txt` 即可。
   - **发正式版**（去掉 `-preview`）时：把每个 `PublicAPI.Unshipped.txt` 的内容（首行 `#nullable enable` 除外）
     追加到同目录 `PublicAPI.Shipped.txt`，Unshipped 清空只留首行。此后再动已 Shipped 的公开面就是破坏性变更，
     必须升主版本。
3. **本地过一遍**（CI 会再跑一次，这里是为了别推上去才发现）：

   ```bash
   dotnet test Piccolo.Forge.slnx -c Release
   dotnet pack Piccolo.Forge.slnx -c Release
   ```

4. 提交（`build: 版本 X.Y.Z`），打带说明的标签并推：

   ```bash
   git tag -a vX.Y.Z -m "Piccolo.Forge X.Y.Z：一句话说明" && git push origin master vX.Y.Z
   ```

5. 看 CI：`gh run watch`。`publish to NuGet` 绿了即发布完成；nuget.org 索引与病毒扫描再要几分钟。

## CI 在做什么（`.github/workflows/ci.yml`）

| job | 触发 | 内容 |
|---|---|---|
| test × 3 | 推送 `v*` 标签（或手动 workflow_dispatch） | ubuntu / windows / macos 上 build + test |
| pack | test 全绿后 | `dotnet pack`，产物作为 artifact |
| publish | `v*` 标签 | Trusted Publishing（OIDC）拿临时 token，`dotnet nuget push --skip-duplicate` |

## 一次性配置（已做，换仓库 / 换账号时才需要重来）

- **nuget.org → 账号 → Trusted Publishing** 建一条策略：Owner `DUANDCHN`，Provider GitHub Actions，
  Repository `DUANDCHN/Piccolo.Forge`，Workflow `ci.yml`，Environment `nuget`，
  Scopes `Push new packages and package versions`，Glob `Piccolo.Forge.*`。
  新建的策略 7 天内要用一次才永久生效。
- **GitHub 仓库 → Settings → Environments** 建 `nuget`（名字必须与策略一致；
  `gh api -X PUT repos/DUANDCHN/Piccolo.Forge/environments/nuget` 一句也行）。
- 工作流 `publish` job 要有 `permissions: id-token: write`，并用 `NuGet/login@v1`（`user: DUANDCHN`）换 token。
- 没有 API key，也不要加：Trusted Publishing 就是为了替掉它。

## 许可证

当前源码的自有代码采用 MIT，NuGet 元数据通过 `PackageLicenseExpression=MIT` 声明。
`LICENSE`、`THIRD-PARTY-NOTICES.md` 和 `licenses/` 全文随包交付，第三方条款不能被 MIT 覆盖。
此次许可变更尚未发布到 NuGet；12.1.1.11 及此前发布的包仍以各包内原有许可为准。
后续首次携带 MIT 许可的发版需要维护者明确决定版本并核对包内实际文件，不覆盖已发布版本。

## 版本规则

- 主版本跟随 Avalonia 主版本（Avalonia 12 → 12.x.y），与 Semi.Avalonia 等包同一惯例；次版本与修订号自增。
- 每次发布都过一遍 Unshipped 里新增了什么，能收的先收成 internal。
- 全部包同版本一起发（`Directory.Build.props` 一处定版本），不单独给某个包升版本。
- 主题包（`Themes.ExpUi` / `Themes.Islands`）与 `Avalonia` 包必须同版本引用——宿主接入指南里已写明。

## 发布后

- LDVision.Studio 自 12.0.1 起以 NuGet 包引用（`ForgeVersion` 一处定版本）；发新版后升那个数字即可。
  12.1.0 起它还应把 `LDVision.Ui*` 三个本地工程删掉、换成本库的控件主题（REQ-072 验收项 ⑤）。
- 包里的 `RepositoryUrl` 指向本仓；公开前按 [开源审查](../open-source-review.md) 核对可见范围和来源声明。
